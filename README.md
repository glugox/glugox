# Glugox Modular Sandbox

This repository hosts a spike for a minimal modular Laravel workflow. The codebase currently focuses on proving the round trip from a bare Laravel install to a locally defined module that exposes an API endpoint.

## What exists today

- **Packages**
  - `packages/glugox/core` &mdash; placeholder service provider that will evolve into the runtime orchestrator.
  - `packages/glugox/module` &mdash; base runtime abstractions that upcoming modules will extend.
  - `packages/glugox/builder` &mdash; reserved for the JSON-driven scaffolder (no logic yet).
- **Sandbox tooling**
  - `sandbox/boot.sh` provisions or reuses `sandbox/laravel-app`, wires the local packages through Composer path repositories, installs them (including the example inventory module), and starts `php artisan serve`.
  - `sandbox/modules/inventory` is a manually crafted example module that registers `/api/inventory/products` and returns an empty array for smoke testing.
  - `sandbox/specs/inventory.json` is the minimal JSON blueprint the builder will eventually consume.

Running `sandbox/boot.sh` leaves a Laravel server running on `http://127.0.0.1:8000` with the example route available at `http://127.0.0.1:8000/api/inventory/products`.

## Immediate roadmap

1. Flesh out the core package with a `ModuleLoader` that can discover modules within `/modules` and register their service providers.
2. Replace the example inventory module with code generated by the builder to validate the JSON-to-module pipeline.
3. Expand the builder to parse the blueprint format and scaffold controllers, service providers, and route files dynamically.
4. Introduce automated checks (tests and linters) inside the sandbox app to cover module registration and routing.

Each step should be implemented incrementally, touching only the files required for that specific milestone to keep the history easy to follow.
